# Support Atelier TryOn

## Recommended funding setup

The recommended first step is **Buy Me a Coffee** for one-off support, with GitHub Sponsors added later if recurring sponsorship becomes useful.

Suggested creator/page names, in order:

1. `ateliertryon`
2. `jewdore`
3. `atelier`

Check availability before publishing. Do not use a page owned by somebody else and do not place a placeholder username in the live GitHub funding file.

### Activation checklist

1. Create and verify the creator page on [Buy Me a Coffee](https://www.buymeacoffee.com/).
2. Use a clear description such as: “Supporting open-source GPU infrastructure and virtual try-on research for Atelier TryOn.”
3. Add three one-time support levels: `Coffee`, `GPU hour`, and `Model evaluation`.
4. Add an optional monthly membership only after there is a real update cadence; do not promise private model access, guaranteed support, or commercial rights.
5. Copy the exact public username into `.github/FUNDING.yml`.
6. Add the same link to the README support section and repository About links.
7. Test the public link in a signed-out browser before announcing it.

### GitHub funding button

After the Buy Me a Coffee username is confirmed, create `.github/FUNDING.yml`:

```yaml
buy_me_a_coffee: YOUR_VERIFIED_USERNAME
```

GitHub reads `FUNDING.yml` from the `.github` directory on the default branch and supports `buy_me_a_coffee: USERNAME`. Keep only verified accounts in the live file.

Until the username is confirmed, this repository intentionally contains `.github/FUNDING.yml.example` instead of an active funding link.

## Non-financial support

Most useful for this project:

- reproducible GPU/driver/model compatibility reports;
- authorized real-motion video samples and quality notes;
- fixes for scheduler recovery, upload safety, and multi-GPU deployment;
- documentation translations and frontend accessibility improvements;
- issue reports with sanitized logs and exact reproduction commands.

## How to check whether support arrived

- Buy Me a Coffee: check the creator dashboard’s supporter/activity view and payout history.
- GitHub: check repository Insights, Issues, Pull Requests, Discussions, Stars, and GitHub Sponsors if enabled.
- Never ask supporters to post private payment receipts, personal media, or private contact information in a public issue.
